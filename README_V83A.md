# BAP v8.3A — Dynamic Translation Correctness Gate

**Status:** runnable differential-correctness prototype, **not** a performance result.

This implements the specification in `docs/v8_3_design_gate.md`. All six schemes operate on the same deterministic initial layout and update log and are checked against an independently maintained flat per-page oracle.

## Six compared models

| Scheme | Eager snapshot (rebuild for semantics) | Immutable snapshot + exceptions |
|---|---|---|
| BAP capped parent decomposition | `bap_eager` | `bap_overlay` |
| Fixed 512-page grid (arbitrary-length last bucket) | `fixed_eager` | `fixed_overlay` |
| Generic globally coalesced ranges | `ranges_eager` | `ranges_overlay` |

All overlay models share precisely the same exception and compaction policy. Every translation record denotes an unmapped gap or a physically contiguous permission-uniform mapping; unsupported hardware page sizes are **not** assumed.

## Exact semantics and checked outcomes

- Initial mappings have deliberate unmapped holes, representative physical fragmentation, and permission boundaries.
- **map:** requires entirely unmapped target interval; supplies explicit PFNs and permissions.
- **unmap:** requires all target pages mapped; invalidates them.
- **protect:** changes r/w/x permissions but retains each PFN.
- **cow_remap:** changes one PFN (and possibly permissions), **not** a full fork/COW lifecycle.
- **lookup:** exact PFN, exact byte offset, r/w/x permission vs protection fault, or unmapped fault.
- Updates are checked after every operation. Small regions (size ≤64 pages) are exhaustively checked every time. Larger regions are checked at changed pages, neighbors, grid and partition boundaries, and deterministic random samples after every operation, plus focused negative tests for invalid updates and out-of-region addresses.
- Per-model updates are validated atomically; selected invalid updates must fail without changing state. A separate self-test covers map/unmap/protect/COW and partial or out-of-bounds invalid operations.
- Physical aliases, shared frames, concurrency, real OS faults, allocator costs, kernel locking, persistence, and hardware TLB fills are excluded.

## Evidence and limitations

The included CSVs were generated by the implementation and the validation command completed with **zero semantic mismatches** in the checked cases. This does not constitute a formal proof for all possible sequences.

**Critical constraint:** The eager models rebuild their snapshot from per-page state on each update. Overlay models also reconstruct a full temporary page vector to validate proposed updates. As a result **this prototype does not implement an efficient incremental update path**. Do not infer update latency or asymptotic performance from `final_base_records`, `final_overlay_exceptions`, or `compactions`. They describe logical representation state only; Python object memory is not measured.

Correctness should be stable across supported Python versions because no unstable Python `hash()` function is used for seeding.

## Next research gate (v8.3B)

Proceed to a separate fair, native incremental implementation **only after** all six models pass correctness on the exact desired operation distributions. Its controls must include fixed-grid+identical overlay, generic-range+identical overlay, and a realistically updateable ordered-range index. Count exact update operations, bytes written, compactions and lookup costs. Compare total time and peak space, not just snapshot record totals.

If a BAP-specific update advantage disappears against those baselines, stop the BAP-specific speedup claim. The design protocol's proposed thresholds (≥10% update time improvement; ≤5% lookup regression; ≤10% peak metadata increase) are hypotheses, not findings.
